# Validation and evidence

## Current verification hierarchy

- Core: .github/workflows/ci.yml proves TypeScript, unit tests, web build, pg0 migrations and SQL roundtrip.
- Optional adapters: .github/workflows/optional-validation.yml includes separate independent gates for Boa execution, OpenTUI native renderer under a PTY, and Tauri Linux compile + .deb creation.
- RuVector in pg0: see docs/experiments/ruvector-pg0.md. pg0's provided extension inventory includes pgvector, not RuVector. Absence must never be reported as a successful RuVector install.
- Servo: research-only (no integrated executable exists); do not call it validated.
- DomainForge: .sea source is illustrative and not compiled/generated by DomainForge. This gate remains open.

Do not interpret a CI job as passed until its own run reports completed/success.

## Core and database

1. bun install; commit bun.lock to lock dependencies.
2. bun run check
3. pg0 start --name project-template --port 5432
4. bun run db:migrate && bun run db:smoke
5. bun run db:ruvector

The smoke covers persistence and rollback; the availability probe covers installed extension inventory, not RuVector execution.

## Optional native checks

- Boa: cargo test --manifest-path experiments/boa/Cargo.toml and cargo run --manifest-path experiments/boa/Cargo.toml.
- OpenTUI: cd experiments/opentui; bun install; bun run typecheck. Under an interactive PTY, bun run probe; assert OPENTUI_RENDERER_OK and terminal restoration. End-to-end keyboard and network tests remain future work.
- Tauri: install OS prerequisites, generate icons, cargo check --manifest-path apps/web/src-tauri/Cargo.toml; bundle a Linux .deb and assert its existence. Packaging success does not prove API lifecycle or production usability.
- RuVector: PostgreSQL 18 ABI proof, CREATE EXTENSION, data/index/query roundtrip, and backup/rollback on each OS.
- Servo: successful embed, DOM compatibility, platform rendering and recovery; no integrated implementation exists.
- DomainForge: validate .sea grammar and compare generated schemas, code and negative tests to the hand-maintained contracts.

## Release gates

No production release until: locked reproducible dependencies, CI green, tested authentication and governance, supported desktop API lifecycle and production origin/CORS, signing, recovery/rollback, and optional dependency validation where selected. An optional adapter that is unselected is not a blocker for the core reference project.
