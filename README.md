# GodSpeed Project Template

A reference stack for typed TypeScript services and self-managed native desktop applications.

**Default stack:** Bun + TypeScript + Valibot (Standard Schema V1) + Kysely + **Postgres.js** + pg0/PostgreSQL, React/Vite, and an optional native Tauri 2 + Rust SQLx desktop route. DomainForge .sea is the semantic modeling source; its TypeScript and Rust projections are not yet generated by the template.

## Two runnable paths

### Browser/API

~~~sh
bun install
cp .env.example .env
pg0 start --name project-template --port 5432
bun run db:migrate
bun run db:smoke
bun run dev
~~~

Open http://127.0.0.1:5173. The Bun API listens on 127.0.0.1:3000. Match DATABASE_URL to the pg0 instance. This example is localhost-only and unauthenticated: do **not** expose it to a network.

### Native desktop without a Bun backend

Tauri uses narrow native IPC commands, Rust SQLx, and a **bundled, checksum-verified pg0 v0.15.2 executable**. On first note operation, it starts its own loopback PostgreSQL instance and initializes the Notes table; at normal exit, it shuts down PostgreSQL while preserving data on disk.

~~~sh
bun install
cd apps/web
bun run desktop:icons
bun run desktop:dev
# Or build an installable desktop bundle:
bun run desktop:build
~~~

The desktop build fetches pg0 during **build**, verifies the release SHA-256, then includes it as a Tauri resource. No Bun HTTP sidecar, external pg0 installation, or container is needed for the installed desktop path. Building requires Rust and OS-specific Tauri prerequisites. Runtime may still require system libraries; pg0 extracts its embedded PostgreSQL engine under the user's profile.

**Validated scope:** Linux CI has installed a .deb, used the packaged application's native smoke mode to write a note, stop/restart PostgreSQL and read it again. The separate installed-GUI open/close and crash-recovery checks are tracked in .github/workflows/optional-validation.yml. Do not infer Windows/macOS or production certification from Linux checks.

## Architecture

| Boundary | Runtime | Database client |
|---|---|---|
| Browser/CLI → Bun HTTP API | Bun + TypeScript | Kysely → Postgres.js |
| Tauri desktop → Rust IPC | Rust + SQLx | SQLx/PostgreSQL via packaged pg0 |
| Both | PostgreSQL | Separate process, local persistent data |

Both database adapters use PostgreSQL. The desktop does **not** secretly use Bun.SQL or Postgres.js; SQLx is the native equivalent at its boundary. Web and native domain contracts still require explicit semantic parity validation.

## Commands and layout

- `just setup`, `just check`, `just dev`, `just desktop-dev`, `just desktop-build`: common task entry points
- `bun run check`, `bun run db:migrate`, `bun run db:smoke`, `bun run db:ruvector`: verification commands
- `apps/api`, `apps/cli`, `apps/web`: HTTP API, headless CLI, React/Tauri
- `packages/contracts`, `packages/core`, `packages/db`: Valibot contracts, domain port/service, Postgres.js persistence
- `experiments/boa`, `experiments/opentui`: isolated native JS execution and TUI references
- `.sea/notes.sea`: validated example DomainForge semantic model
- `stack.toml`, `AGENTS.md`, `docs/`: accepted selections, agent constraints, evidence/architecture

See `docs/architecture.md`, `docs/validation.md`, and `docs/decisions/` for tradeoffs and explicit acceptance gates.

## RuVector and deferred integrations

**RuVector has a PostgreSQL extension:** https://github.com/ruvnet/RuVector/tree/main/crates/ruvector-postgres . It is not included in pg0 by default. The extension source currently requires a verified PostgreSQL-18-compatible build, deployment into pg0's exact library/extension directories, and real index/query/restart tests. See `docs/experiments/ruvector-pg0.md` and issue #1. The existing pgvector extension is not equivalent evidence.

Servo browser embedding, real Windows/macOS Tauri packaging and lifecycle tests, automatic .sea → TS/Rust code generation, release signing, production authorization and secure credential provisioning remain separate gates.

## Security and production scope

This is a **local-first development template**. The desktop employs loopback PostgreSQL and a random on-disk database credential, but provisioning currently passes that secret as a process argument, and Windows ACLs, credential hardening, crash recovery, backups, upgrades and concurrency still require audits. The GUI is not a production-certified app. Browser/API authentication is not implemented. Never expose its API to public interfaces.

## Experimental browserless React renderer

An opt-in [Boa + Blitz + React 19/Astryx probe](experiments/native-react-blitz/README.md) is available with `just native-render-preact` and `just native-render-astryx`. This tests a possible browserless desktop renderer without altering the verified Tauri/WebView desktop route. **React DOM/Astryx compatibility with Boa/Blitz is not yet established.**

## Reuse this repository

Enable **Template repository** in GitHub Settings → General to get the *Use this template* action. Rename `@template/*` package names, app/instance identifiers and Tauri bundle identifier, then replace Notes with your own domain. On first installation, commit the generated `bun.lock` and Cargo lockfile after validation; run the actual target platform matrix before shipping.

Preserve the evidence standards: affordances are routes demonstrated by executable settlement, not merely a list of optional technologies.
